## Design

**Furniture type (`ComputerFurniture`).**
- A `FurnitureSO` (id **917001**) is copied from an existing one: our price, `IsMainFurniture`, and the most common furniture `BoxSize`.
  - It's added to `IDManager.m_Furnitures` (on `IDManager.Awake`, `CartManager.Initialize` and `FurnituresViewer.SpawnFurnitures`).
  - `IDManager.FurnitureSO(917001)` is answered directly.
  - Name: `LocalizationManager.LocalizedFurnitureName` → "Computer".
  - Box label: `ProductAtlasManager.SetFurnitureIcon` → our own material.
- The prefab template lives under an inactive `DontDestroyOnLoad` holder, so nothing in it ever runs `Awake`. It's built once per game run as a copy of the store computer's root (`m_PlacingMode.m_Furniture`, "Computer &&"):
  - kept: meshes, the root's layer-6 box colliders (what the interaction raycast hits, so `Furniture` on the root is the `IInteractable`), `NavMeshObstacle`, `Highlightable`, snap points, the "Placing Mode" child (`Rigidbody`, `BoxCollider`, `FurniturePlacingMode`) and the placing mode's `m_InteractionZoneCanvas` subtree untouched;
  - removed: the PC camera (`m_PCCam`), every other canvas subtree (the screen UI), and every other script (`Computer`, `ComputerOperatingSystem`, `MusicPlayerManager`, `NetworkComputer`, `NetworkMarketShoppingCart`, ...). Renderers left under `m_ComputerScreen` get suffix `#ecscreen` (none expected: the screen is all canvases);
  - `FurniturePlacingMode` references were remapped into the copy by `Instantiate`; `m_Furniture` and `m_ParentPhotonView` are re-set explicitly;
  - added: `PhotonView` + `PhotonTransformViewOptimized` (the store computer has neither; settings copied from a real furniture prefab, see Status v1.3.0), `Furniture` (`m_ID` 917001, `m_PlacingMode`, `m_PhotonView`, `m_NetworkFurniture`) and `NetworkFurniture`. The game has no `Furniture` subclasses; `Furniture.Start` only lazily looks up `InteriorSpotLight`/`Speaker`, and `get_PhotonView`/`OwnNetworkFurniture` fall back to `GetComponent`;
  - `PhotonView`: `sceneViewId` = 0 (a fresh component), `ObservedComponents` = [the transform view], `OwnershipTransfer`/`Synchronization`/`observableSearch` copied from the reference (`NetworkFurniture.OnPhotonInstantiate` transfers ownership to the unboxing player; `Fixed` would ignore that, so it is replaced by Takeover). `PhotonView.Awake` clears and refills `ObservedComponents` itself when `observableSearch` isn't Manual.
  - `Furniture.m_ID` = 917001 is serialized, so it survives `Instantiate`.
  - The session code uses the furniture root itself as the "model" (same layout as the store computer's root).
- Spawning: both `FurnitureGenerator.SpawnFurniture` overloads are replaced for our id.
  - Offline: `LeanPool.Spawn(template)`.
  - Host: `PhotonNetwork.InstantiateRoomObject("Furnitures/ExtraComputers/ExtraComputer", ..., {boxViewId})`. Box view id is `-1` when loading a save, as in vanilla.
  - Save load never returns null (inactive stand-in, review round 5 F1). Unboxing faces the user side towards the player (F4).
  - The template is put in `DefaultPool.ResourceCache` under that id. A `DefaultPool.Instantiate` prefix builds it on demand on guests.

**Using one (`ComputerSession`).**
- `Furniture.InstantInteract` prefix, for our id and not while being placed:
  1. Moves the real `m_ComputerScreen`, `m_PCCam` and `m_PlayerPosition` under scene-root anchors. Each anchor mirrors that part's parent, transposed from the store computer's root to the extra computer's model.
  2. Hides the extra computer's own `#ecscreen` renderers.
  3. Calls the vanilla `Computer.InstantInteract`, with `IsOccupied` forced false for the call and restored afterwards.
  4. Sets `PlayerInteraction.m_CurrentInteractable` to the computer, so `Interact` activates `ComputerInteraction` (type 7). Pointing it at the furniture would throw in `ComputerInteraction.set_Interactable`, which casts to `Computer`.
- `NetworkComputer.InteractComputer_Broadcast` is skipped while the session is active, so other players never see the store computer as occupied.
- End of session:
  - The `Computer.Back` postfix ends it after Back has placed the player at the relocated `m_PlayerPosition`.
  - A `set_OpenPC(false)` outside Back also ends it.
  - The parts are restored to their original parent, local pose and sibling index.
- The anchors follow the model every frame (`Computer.LateUpdate` postfix). They aren't children of the furniture, so boxing up a computer someone is using doesn't destroy the real UI.
- Furniture getters for our id: `InteractionType` → BOTH, `InstantInteractionHint` → `_interact`.

## Multiplayer reasoning

- Each client has exactly one computer UI and one local player, so borrowing it gives every player an independent session. Nothing about the session is networked except the avatar's position, which the vanilla `InstantInteract` and `Back` set.
- Data changes go through the same networked code paths as on the store computer.
- Furniture is host-spawned room objects. Guests need the mod for the prefab id, the `FurnitureSO` (box setup, `IDManager.FurnitureSO`) and the interaction patches. An unmodded guest gets Photon "prefab not found" errors and null `FurnitureSO` exceptions on boxes: `FurnitureBox.Initialize` and `Setup` dereference `IDManager.FurnitureSO(id)` without a null check (ISIL, jump to the NRE thrower).
- **Guard for unmodded players (`Presence.cs`).** Modded clients publish Photon player properties (`flamboyanthopper.extracomputers` bool, `.price` float from the master, `.use` int PhotonView id of the computer in use). Only `RoomPlayerPropsListener` reads player properties, and only `png`/`sid`, so extra keys are inert for unmodded clients (checked in PlayerCrouch's review). `Presence.Tick` runs about once a second from the `Computer.LateUpdate` postfix (publish, price sync, log when the blocked state changes, show/hide the shop item).
  - While any other player lacks the property (config `ProtectUnmoddedPlayers`, default on), the host: hides the shop entry (`FurnitureSalesItem.Setup` postfix remembers it; `SpawnFurnitures` only runs once per scene, so the item is toggled with `SetActive`), refuses `MarketShoppingCart.Purchase` with a computer in the cart (the host's own click and a guest's `Purchase_Request` -> `Purchase_Response` both end there; guests skip the check because `IsConnectedAndSlave` only sends a request), and refuses `FurnitureBoxInteraction.NetworkOpenBox` for a computer box. Verified in the ISIL: the host's own click goes `OnUse` -> `OpenFurnitureBox_Broadcast` -> `NetworkOpenBox`, a guest's click goes `OpenFurnitureBoxRequest` -> RPC -> `OpenFurnitureBoxRequest_RPC` -> `NetworkOpenBox` (no broadcast method in between), and `NetworkOpenBox` has no other callers. On the host's path nothing else changes state first; on a guest's path only `m_InAnimationTransition` is set and reset by a delayed call.
  - Fails open: errors never block. Not covered, only documented: computers and boxes that exist before the player joins (placed ones, saved boxes, items in the cart, which `CartManager.OnSyncRequest` sends as JSON; what the unmodded guest's cart UI does with an unknown furniture id wasn't checked). Spawning in `ComputerSpawner` only warns, since refusing a save-load spawn would lose the computer.
  - Reading the property: `Presence.GetMod` distinguishes absent / false / true / unreadable. Unreadable (an `Unbox<bool>` failure) counts as modded and warns once, so a read problem can't lock everybody out. With `VerboseLogging`, `Other players: <name>: mod=Yes (raw True); ...` is logged whenever it changes; check it in test step 4.
  - The shop item is re-asserted every frame from a cached state (refreshed once a second), so a shop UI that re-activates its items doesn't flicker.
  - No custom popup text exists in the game (`RaiseInteractionWarning` shows fixed localized texts per `InteractionWarningType`), so refusals are log-only on the host; the shop item being hidden is the visible cue.
- **Price** is a constant (1000) on every client since 1.4.2 (before: a per-client config), but `So.Cost` also drives the cart UI. The host publishes its price; guests with the mod apply it (`Presence.EffectivePrice`). The host charges its own `So.Cost` anyway.
- **In use marker:** a player on an extra computer publishes its PhotonView id as `flamboyanthopper.extracomputers.use`; `ComputerSession.TryStart` refuses (`IN_USE_BY_OTHER_PLAYER` warning) if another player has the same id. Race between two simultaneous opens is possible and harmless (avatars overlap).
- `NetworkComputer.OnSyncRequest` (late joiners) sends the host's `IsOccupied`. The session restores it, so a host on an extra computer doesn't make the store computer look occupied.

## Game reference: furniture shop and the store computer

Verified in the dumps; not yet confirmed in-game. (Moving and placing furniture, `FurniturePlacingMode`, and the fact that there are no `Furniture` subclasses are in the root CLAUDE.md, section 8.)

**Furniture pipeline.**
- A furniture type is a `FurnitureSO` {`ID`, `BoxSize`, `FurnitureIcon` (shop sprite), `AtlasIndex`/`AtlasPosition` (box label), `FurniturePrefab`, `FurnitureColor`, `IsMainFurniture`, `Cost`} in `IDManager.m_Furnitures`. `IDManager.FurnitureSO(id)` is a FirstOrDefault over it, used by the cart, the delivery, `FurnitureBox`, box-up and the spawner.
- Shop: `FurnituresViewer.SpawnFurnitures` lists the SOs with `IsMainFurniture`, skipping id 7000. Names come from `LocalizationManager.LocalizedFurnitureName(id)`. Cart totals multiply by `Cost`.
- Box label: `ProductAtlasManager.SetFurnitureIcon(id, renderer)` sets `sharedMaterial = atlasedMaterials[AtlasIndex]`, then a `_BaseMap` texture offset.
- Spawning: `FurnitureGenerator.SpawnFurniture`, with two overloads: (id, pos, boxViewId) for unboxing and (id, pos, rot, parent) for loading a save.
  - Offline: `LeanPool.Spawn(prefab)`.
  - Online (master only): it branches on the prefab's component type to `NetworkObjectGenerator.SpawnNetwork<Type>`, which calls `PhotonNetwork.InstantiateRoomObject("Furnitures/<Type>/" + prefab.name, pos, rot, 0, {boxViewId})`.
  - Photon uses the stock `DefaultPool`: `ResourceCache` first, then `Resources.Load`. Adding a GameObject to `((DefaultPool)PhotonNetwork.PrefabPool).ResourceCache[id]` makes any prefab network-instantiable.
  - `NetworkFurniture.OnPhotonInstantiate` reads `data[0]` (the box interaction's view id), transfers ownership to that player and calls `FurnitureBoxInteraction.OpenBoxOrder` to start placing.
- **A null spawn while loading a save breaks the load** (ISIL, `FurnitureManager::LoadFurnitureDatas`, called from `LoadSaveProgress` ← `Awake`, host/offline only): it logs "Can't spawn furniture with id: N" and then dereferences the null anyway (NRE; the loop has only a try/finally). Every furniture entry after it in `m_FurnituresDatas` is not spawned. Vanilla does the same for an unknown id (the overload logs "Furniture couldn't find : N" and returns null). Per spawned object it needs only `GetComponent<Furniture>()` (then `set_Data`, which sets the pose, and `SetCollisions(go, true)`). `Furniture.OnEnable` subscribes `OnSave` (writes position and rotation into its `Data`); `m_FurnituresDatas` itself is the saved list (`AddFurniture` on place, `RemoveFurniture` on box-up).
- **Two prefab versions per furniture.** `FurnitureSO.FurniturePrefab` is the plain scene-asset prefab (no `PhotonView`). The networked one is a separate asset under `Resources/Furnitures/<folder>/<name>` (folders `Trash`, `Vendings`, `Displays`, `Racks`, `Checkouts`; `IceCream/IceCreamStand`, `PaintBucket`), with root `PhotonView` + `PhotonTransformViewOptimized` + a Network* script (resources.assets, checked with `tools/unity_components.py`). Only Trash among those checked has the plain `Furniture` component (+ `NetworkFurniture`); the shelf, stall and vending prefabs have only their own type script. Serialized transform-view values on Trash, Stall and VendingMachine are identical.
- Every type in the shop has its own network spawner, so a mod can't count on finding a "plain" furniture prefab to copy (the donor search found none in-game).
- `Furniture.m_ID` is serialized in the prefab; nothing sets it at runtime. Saves are `FurnitureManager.m_FurnituresDatas`; for loading see the null-spawn point above.
- Assets: the furniture icon atlas `T_IconAtlas_Furnitures` (sharedassets2) has no computer. Flat white UI glyphs are named `icon_<set>_<n>`; `icon_device_63` is a computer.

**Store computer** (`__Project__.Scripts.Computer.Computer`; one per scene, and several managers hold a reference to it, so it can't be cloned).
- It isn't a `Furniture`, but it has its own `m_PlacingMode` and can be moved.
- `InstantInteract`:
  - refuses if `IsOccupied` (another player is on it);
  - otherwise `set_OpenPC(true)` activates `m_PCCam`, a camera that looks at the world-space canvases under `m_ComputerScreen`;
  - sets `OccupiedPlayer` and, online, `NetworkComputer.InteractComputer_Broadcast(true)` (receivers only set `IsOccupied` / `OccupiedPlayer`);
  - puts the avatar in front of the cam.
- `Back()` (called from `ComputerInteraction.OnCancel` / `GamepadBack`) does `set_OpenPC(false)` (which broadcasts false), then puts the player at `m_PlayerPosition`.
